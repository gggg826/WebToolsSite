# IT365 工具箱 - 工具编写规范

## 1. 规范概述

本文档定义了 IT365 工具箱项目中工具开发的统一规范，确保所有工具具有一致的结构、风格和质量。

**核心原则**：
- **统一性**：所有工具遵循相同的结构和接口
- **独立性**：工具之间互不依赖，可独立开发和维护
- **可扩展性**：易于添加新功能和优化
- **用户友好**：简洁明了的界面和交互
- **性能优先**：快速响应，不阻塞 UI

---

## 2. 工具目录结构

每个工具必须按以下结构组织：

```
src/tools/{category}/{tool-name}/
├── index.tsx           # 工具主组件（必需）
├── config.ts           # 工具配置文件（必需）
├── utils.ts            # 工具业务逻辑（必需）
├── types.ts            # 类型定义（可选）
├── constants.ts        # 常量定义（可选）
├── components/         # 工具私有组件（可选）
│   ├── Input.tsx
│   └── Output.tsx
└── README.md           # 工具文档（推荐）
```

**说明**：
- `{category}`：工具分类（text/dev/image/data/other）
- `{tool-name}`：工具名称（kebab-case，小写字母和连字符）

## 4. 工具组件规范（index.tsx）

### 4.1 组件结构

```typescript
// src/tools/text/json-formatter/index.tsx
import { useState } from 'react';
import { useTranslation } from 'react-i18next';
import { Button } from '@/components/common/Button';
import { Input } from '@/components/common/Input';
import { formatJson, compressJson } from './utils';

export default function JsonFormatter() {
  const { t } = useTranslation();

  // 状态管理
  const [input, setInput] = useState('');
  const [output, setOutput] = useState('');
  const [error, setError] = useState('');

  // 事件处理
  const handleFormat = () => {
    try {
      const formatted = formatJson(input);
      setOutput(formatted);
      setError('');
    } catch (err) {
      setError(t('tools.text.json-formatter.error.invalid'));
    }
  };

  // 渲染
  return (
    <div className="tool-container">
      <div className="tool-section">
        <h3>{t('tools.text.json-formatter.input.title')}</h3>
        <textarea
          value={input}
          onChange={(e) => setInput(e.target.value)}
          placeholder={t('tools.text.json-formatter.input.placeholder')}
          className="tool-textarea"
        />
      </div>

      <div className="tool-actions">
        <Button onClick={handleFormat}>
          {t('tools.text.json-formatter.actions.format')}
        </Button>
      </div>

      {error && <div className="tool-error">{error}</div>}

      <div className="tool-section">
        <h3>{t('tools.text.json-formatter.output.title')}</h3>
        <pre className="tool-output">{output}</pre>
      </div>
    </div>
  );
}
```

### 4.2 组件规范

1. **导入顺序**：
   ```typescript
   // 1. React 相关
   import { useState, useEffect } from 'react';

   // 2. 第三方库
   import { useTranslation } from 'react-i18next';

   // 3. 项目公共组件
   import { Button } from '@/components/common/Button';

   // 4. 工具内部模块
   import { formatJson } from './utils';
   import { JsonOptions } from './types';
   ```

2. **组件命名**：
   - 使用 PascalCase
   - 名称应清晰描述工具功能
   - 导出为默认导出：`export default function ToolName() {}`

3. **状态管理**：
   - 使用 `useState` 管理本地状态
   - 避免不必要的状态
   - 复杂状态考虑使用 `useReducer`

4. **国际化**：
   - 所有用户可见文本必须使用 `t()` 函数
   - 国际化键格式：`tools.{category}.{tool-name}.{section}.{key}`

5. **事件处理**：
   - 使用 `handle` 前缀命名：`handleFormat`、`handleCopy`
   - 业务逻辑应放在 `utils.ts` 中，组件只负责调用

6. **错误处理**：
   - 必须使用 `try-catch` 捕获错误
   - 友好的错误提示（国际化）
   - 避免应用崩溃

7. **样式**：
   - 使用 Tailwind CSS 类名
   - 使用预定义的工具样式类（见样式规范）

## 5. 业务逻辑规范（utils.ts）

### 5.1 函数规范

```typescript
// src/tools/text/json-formatter/utils.ts

/**
 * 格式化 JSON 字符串
 * @param input - 输入的 JSON 字符串
 * @param indent - 缩进空格数（默认 2）
 * @returns 格式化后的 JSON 字符串
 * @throws {Error} 如果输入不是有效的 JSON
 */
export function formatJson(input: string, indent: number = 2): string {
  try {
    const parsed = JSON.parse(input);
    return JSON.stringify(parsed, null, indent);
  } catch (error) {
    throw new Error('Invalid JSON format');
  }
}

/**
 * 压缩 JSON 字符串
 * @param input - 输入的 JSON 字符串
 * @returns 压缩后的 JSON 字符串
 * @throws {Error} 如果输入不是有效的 JSON
 */
export function compressJson(input: string): string {
  try {
    const parsed = JSON.parse(input);
    return JSON.stringify(parsed);
  } catch (error) {
    throw new Error('Invalid JSON format');
  }
}

/**
 * 验证 JSON 字符串
 * @param input - 输入的字符串
 * @returns 是否为有效的 JSON
 */
export function isValidJson(input: string): boolean {
  try {
    JSON.parse(input);
    return true;
  } catch {
    return false;
  }
}
```

### 5.2 规范要点

1. **函数命名**：
   - 使用 camelCase
   - 动词开头，清晰描述功能
   - 例：`formatJson`、`validateInput`、`calculateHash`

2. **JSDoc 注释**：
   - 必须为每个导出函数添加 JSDoc
   - 包含：功能描述、参数说明、返回值、异常情况

3. **纯函数优先**：
   - 尽量使用纯函数（无副作用）
   - 便于测试和维护

4. **错误处理**：
   - 抛出明确的错误信息
   - 使用 Error 对象

5. **性能考虑**：
   - 大数据处理使用 Web Worker（如适用）
   - 避免阻塞主线程

## 11. 性能优化

### 11.1 大数据处理

对于需要处理大量数据的工具，应使用 Web Worker：

```typescript
// src/tools/text/json-formatter/worker.ts
self.onmessage = (e) => {
  const { type, data } = e.data;

  try {
    if (type === 'format') {
      const formatted = JSON.stringify(JSON.parse(data), null, 2);
      self.postMessage({ success: true, data: formatted });
    }
  } catch (error) {
    self.postMessage({ success: false, error: error.message });
  }
};

// 在组件中使用
import { useEffect, useRef } from 'react';

function JsonFormatter() {
  const workerRef = useRef<Worker>();

  useEffect(() => {
    workerRef.current = new Worker(
      new URL('./worker.ts', import.meta.url),
      { type: 'module' }
    );

    workerRef.current.onmessage = (e) => {
      const { success, data, error } = e.data;
      if (success) {
        setOutput(data);
      } else {
        setError(error);
      }
    };

    return () => workerRef.current?.terminate();
  }, []);

  const handleFormat = () => {
    workerRef.current?.postMessage({ type: 'format', data: input });
  };
}
```

### 11.2 防抖处理

对于实时处理的功能，应使用防抖：

```typescript
import { useDebouncedCallback } from '@/hooks/useDebouncedCallback';

function MyTool() {
  const debouncedProcess = useDebouncedCallback(
    (value: string) => {
      // 处理逻辑
    },
    500 // 500ms 延迟
  );

  const handleInputChange = (e: React.ChangeEvent<HTMLTextAreaElement>) => {
    const value = e.target.value;
    setInput(value);
    debouncedProcess(value);
  };
}
```
